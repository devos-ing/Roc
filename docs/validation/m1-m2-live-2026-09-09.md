## Defects found and fixed

GitHub's label-filtered lists briefly omitted newly created Issues. Publication now checks an unfiltered repository list before deciding to create, and verifies returned Issue numbers directly against the fixed repository. Repeating publication during label lag does not create duplicates. Direct readback also retains the 1,000-result bound.

A 250ms shutdown drain expired while real GitHub checkpoint acknowledgement was still pending. The drain now permits five seconds; failed or timed-out cleanup still retains ownership, and the independent backend-close limit is unchanged. Cancellation after confirmed publication now leaves awaiting_merge and done checkpoints unchanged. Issue #2 retains the historical cancellation message from the pre-fix run; its PR, successful attempts and acceptance checks are confirmed.

## Sandbox and measurement limits

An outside-write canary and a read of the original Pi credential file were denied. Each Pi role could write its own worktree plus isolated Pi, home and temporary directories. The GitHub controller used the user's gh account against this private repository. Network access remained enabled for model calls; this was filesystem sandboxing, not a VM or network sandbox.

Recorded input plus output usage was 191,211 tokens, including 95,232 cached input tokens. Usage is complete for the recorded attempts. Setup failures made no model calls. There was no sequential-versus-parallel benchmark, so these results establish working execution and isolation, not a token-saving percentage or speedup factor. The refill happened while the slower task was publishing its PR, after its model roles had ended.

Detailed checkpoints, activity timelines, sandbox probes and cleanup recovery notes are in .scratch/deliver-code/live-github-acceptance/. Copied credentials are excluded from the repository and removed after the test processes stop.
